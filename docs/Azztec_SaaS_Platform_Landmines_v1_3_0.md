## A. Python / FastAPI

- **Never do DB I/O inside `async def`.** pyodbc is synchronous; a blocking call in an `async def` route stalls the whole event loop. Use plain `def` routes (FastAPI runs them in anyio's threadpool, default 40 threads) or `run_in_threadpool`. Async comes back only at PG-only with `psycopg` async. [2026-09-10]
- **A logger with no handler and no level is silent for INFO and leaks ERROR to stderr.** `logging.getLogger("x")` inherits root's WARNING, so `INFO` records die at the **level check** before any handler would be consulted, and `ERROR` records escape through `logging.lastResort` — a WARNING-level stderr handler with no formatter. uvicorn's `LOGGING_CONFIG` configures the `uvicorn*` loggers only; it has no `root` key, so nothing fills the gap. A library logger needs a **level and a handler**, set by the application. [2026-09-11]
- **`Logger.hasHandlers()` is useless as a "am I wired?" guard.** It walks ancestors, so under pytest the caplog handler on root satisfies it — the check passes in the suite while the dev console stays silent. Test the specific handler you attached, by name. [2026-09-11]
- **A `StreamHandler` binds its stream object at construction, and pytest moves `sys.stdout` twice.** The default `--capture=fd` is not only an fd redirect: its `SysCapture` half replaces `sys.stdout`, and the `capfd` fixture replaces it **again** on entry. A handler built before the fixture keeps writing to the previous object — the line shows up in the report's "Captured stdout call" section while `capfd.readouterr()` comes back empty. Resolve the stream at **emit** time with a `stream` property, exactly as the stdlib's own `logging._StderrHandler` does. capfd is the right reader; it is not a way around construction-time binding. [2026-09-11]
- **A catch-all route under an API prefix defeats Starlette's 405.** `Router.app` collects a `Match.PARTIAL` for a real route with a wrong method but only falls back to it when **no** route returns `Match.FULL`. A later `/api/{rest:path}` full-matches on path and wins, turning `POST /planner/range` into a 404. Fix missing-route behaviour at the mount, never with a catch-all. [2026-09-11]
- **`app.frontend()` on a missing `dist/` raises at request time, not at mount.** `RuntimeError: StaticFiles directory '…' does not exist` surfaces as a **500**, so any `/api/...` miss depends on the SPA mount being healthy. Mount conditionally on `dist/index.html` existing; the miss then reaches the app's `StarletteHTTPException` handler as a proper JSON 404. [2026-09-11]
- **`app.frontend()` fallback** serves `index.html` only for `GET`/`HEAD` with `Accept: text/html`; missing JS/CSS still 404; `POST` to an SPA path is 404. Keep the API under `/api/v1` so SPA routes never collide with path operations (path operations always win anyway). `check_dir="auto"` errors on a missing `dist/` unless `FASTAPI_ENV=development` (`fastapi dev` sets it). [2026-09-10]
- **`fastapi dev` imports the app module twice** — once in the reloader parent to resolve the import string, once in the watchfiles child. Anything at module scope, including `app = create_app()`, runs in both processes. Keep `create_app()` free of side effects beyond logging, or every boot double-writes. [2026-09-11]
- **`from` is a Python keyword and the trap bites twice.** A contract key `from` needs `Field(alias="from")` on the model **and** `Query(alias="from")` on the route parameter — two independent declarations, either of which can regress alone. Assert both: the runtime body *and* the published OpenAPI schema. It will bite a third time in the generated TS client. [2026-09-11]
- **`/health` must read `__version__`, never a literal.** A hardcoded version string in the health payload is stale the moment the module bumps, which is precisely the lie the bump rule exists to prevent. Pin it with a test that compares the payload to the modules' own constants. [2026-09-11]
- **Ruff config bans two habits from the start:** `%`-formatting (UP031) and `Depends()` in an argument default (B008). Write f-strings and `Annotated[T, Depends(...)]` in the first draft — retrofitting them is a version bump with no behaviour change. Exception: a file under a 1:1 parity contract keeps `'%s' %` behind a file-wide `# ruff: noqa: UP031` (see §D). [2026-09-11]
- **The CI dialect gate greps the whole `sql.py` file**, docstrings and comments included. A banned token spelled out in prose fails CI while a statement-only unit test passes. Make the test read exactly what the gate reads. [2026-09-11]
- **`ruff format` before `ruff check` and pytest.** Delivered files are not format-clean on arrival; the format step in the smoke is load-bearing, not cosmetic. [2026-09-11]
- **Dependencies with `yield` and BackgroundTasks:** the post-`yield` lifecycle has changed across releases (0.106, later 0.118-era refinements). Rule: a background task opens its **own** connection; never reuse the request's yielded session in a task. [2026-09-10]
- **FastAPI 0.137.0 refactored routers** — `router.routes` is now a tree of intermediate objects, not a flat list. Anything that iterates `router.routes` (custom OpenAPI hacks, route listing, contract tests) breaks. Use `app.openapi()` or `iter_route_contexts()` instead. [2026-09-10]
- **`fastapi[standard]` pulls in `fastapi-cloud-cli`**; use `fastapi[standard-no-fastapi-cloud-cli]` if you don't want the `fastapi login/deploy` commands. [2026-09-10]
- **Pydantic v2 serialises `Decimal` as a JSON string.** MSSQL `numeric` columns arrive as `Decimal` from pyodbc → the planner contract expects numbers → coerce with the `_i()`/`_f()` twins in the row mapper before building models, or declare fields `float`. [2026-09-10]
- **Naive datetimes.** MSSQL `datetime` comes back naive; the contract wants `yyyy-MM-dd` strings (`iso()`) and `HH:mm` (`timeOf()`). Format explicitly in the mapper; never let Pydantic emit `2026-09-18T00:00:00`. [2026-09-10]
- **Windows has no tz database.** `ZoneInfo("Pacific/Auckland")` raises `ZoneInfoNotFoundError` unless the `tzdata` wheel is installed. It is in the pyproject; don't remove it. [2026-09-10]
- **DST day arithmetic:** the Ignition bug (`system.date.daysBetween` asymmetric across 27 Sep 2026) is reproducible in Python if you subtract aware datetimes. `civil_days()` = `(date_b - date_a).days` on `datetime.date` objects only. Test 17→29 Sep = 12 and 29→17 Sep = −12. [2026-09-10]
- **`round()` is banker's rounding in Python 3** (`round(2.5) == 2`); Jython 2.7 rounded half away from zero. `pct = int(round(100.0 * planned / capacity))` can differ by 1 at exact .5 — decided OD-8: keep Python 3 semantics, documented not patched. [2026-09-10]
- **`get_settings()` is `lru_cache`d.** A watchfiles reload does **not** pick up a `.env` change — restart the server. Any test that flips env must call `get_settings.cache_clear()`. And `.env` edits have silently failed to reach disk from a chained PowerShell heredoc: verify with `Select-String` before blaming code. [2026-09-11]
- **uv on Windows:** install via the standalone installer or winget, then open a **new** terminal (PATH). `uv run` always uses the project venv — never `pip install` into it by hand. `uvx` = `uv tool run`. `uv run` must be invoked from inside the project, or it reports `program not found`. [2026-09-11]
- **Windows PowerShell 5.1 reads a BOM-less UTF-8 `.ps1` as ANSI.** Non-ASCII in a script (a `§` in a banner) renders as `Â§`. Delivered `.ps1` files are ASCII-only, or carry a BOM. [2026-09-12]
- **A new PowerShell window opens in `C:\windows\system32`.** Every pasted block starts with `cd C:\dev\workmate-saas…`, or the first four commands fail on path and the fifth does something in the wrong tree. [2026-09-12]
- **The `app.frontend()` mount branch emits nothing.** With `dist/` present, the only boot-time evidence is the absence of `[G] frontend not built`. Log a positive `[F] frontend mounted dist=…` line; an absence is only evidence when the whole sequence is visible. [2026-09-12]
- **The diag middleware is scoped to `/api`.** `GET /` gets a uvicorn access line and no diag line; `/api/v1/…` misses do. Deliberate or not, an SPA request is invisible to the forensic log — write the scope down where the middleware lives. [2026-09-12]
- **Once `dist/` exists, an `/api/…` miss with `Accept: text/html` is served `index.html` AND logged `[F] … 200`** — the instrument reports an API miss as a hit. `curl`/`TestClient` send `*/*` and still get the JSON 404, so the suite stays green while a browser typo on an API path silently "succeeds". S7 fixes the mount; until then, read the `[F]` on an `/api/` path with suspicion if the status is 200 and the path is not a route. [2026-09-12]
- **A slice that creates or changes `web/dist` changes backend behaviour without touching backend source.** Re-run the backend suite with `dist/` present before committing; `test_root_matches_the_frontend_state` was written to survive the flip and did. [2026-09-12]
- **`uv` defaults new interpreters to 3.14** now; this project pins `.python-version` = 3.13 until wheels are verified. [2026-09-10]
- **Delivered `.py` files no longer pass through a markdown renderer** (that was the Ignition Script Console path) — bare URLs and backslashes are safe again. But files are still delivered as raw source, never inline, and **`Unblock-File` in `Downloads` is not a copy**: check `Length` on the *target* after every drop. A smoke that reproduces the previous failure exactly is evidence the drop failed, not that the fix failed. [2026-09-11]

## B. SQLAlchemy / pyodbc / MSSQL / PostgreSQL

- **ODBC Driver 18 defaults to `Encrypt=yes`** and rejects the local instance's self-signed certificate: `SSL Provider: The certificate chain was issued by an authority that is not trusted`. Dev fix: `TrustServerCertificate=yes` in the connection string (already in `.env.example`). Prod: a real cert or `Encrypt=strict` with a trusted CA. [2026-09-10]
- **URL-encode the ODBC string:** build with `urllib.parse.quote_plus(...)` and `mssql+pyodbc:///?odbc_connect=…`. A raw `Driver={ODBC Driver 18 for SQL Server}` in the URL breaks on the braces/spaces. `db.py` does this. [2026-09-10]
- **Never key a cache on the engine URL.** The MSSQL `odbc_connect` URL carries the password in its query string and SQLAlchemy's `hide_password` does not mask it — a URL-keyed cache parks the service account's password in a module global. Key on the `Engine` object. [2026-09-11]
- **Double pooling:** pyodbc pools connections itself; SQLAlchemy pools too. Set `pyodbc.pooling = False` **before** `create_engine` (SQLAlchemy's own recommendation for the mssql dialect). `db.py` does this. [2026-09-10]
- **`fast_executemany=True`** on the engine for bulk inserts; `pool_pre_ping=True` to survive idle-connection drops. [2026-09-10]
- **`char(n)` padding:** every legacy `char` column (`Short_WO_Id char(25)`, `Status char(1)`, `WO_Title char(70)`, `Users.Active char(1)`…) comes back space-padded. `RTRIM()` in SQL as the Ignition code does **and** `.strip()` in the mapper; compare with `RTRIM(x) = 'Y'`, never `x = 'Y'` unless you know the column is `varchar`. [2026-09-10]
- **`:name` in a SQL comment is a bind parameter** for SQLAlchemy `text()` too (regex-based, comments are not stripped) — the Ignition COLON-IN-COMMENT landmine survives. No colons in SQL comments; escape a literal colon as `\:`. [2026-09-10]
- **`OFFSET … FETCH` needs `ORDER BY`** on MSSQL. `TOP 1` in correlated subqueries (the pin select) is MSSQL-only → `-- PG-CONVERT: TOP 1 -> LIMIT 1`. [2026-09-10]
- **No `CAST(NULL AS datetime)` in portable SQL.** `datetime` is not a PostgreSQL type name and MSSQL's `timestamp` is rowversion. Use a bare `NULL` — the value is `None` either way. [2026-09-11]
- **`GROUP BY … ORDER BY COUNT(*) DESC` with no tie-break is non-deterministic**, and worse when the answer is cached for the process lifetime. Always add a second key (`, UOM_Id`). Latent on one database is still a defect on the next. [2026-09-11]
- **`SCOPE_IDENTITY()` vs `RETURNING`:** never write either in module SQL; call `db.insert_returning_id(conn, sql, params)`. Avoid `OUTPUT INSERTED.*` — it fails on tables with triggers, and a 20-year-old DB has triggers. [2026-09-10]
- **MSSQL `datetime` precision is 3.33 ms** and `Request_Start_Date` carries a time of day on ~half the rows (probed at KT 2026-09-04; re-probe on RST). Key days on the DATE part; shift datetimes with wall-clock `timedelta(days=n)` (DST-safe because naive). [2026-09-10]
- **Legacy stored procedures return row counts** that confuse `fetchall()`; when calling a `wmsp_*` proc prefix `SET NOCOUNT ON;` in the same batch. Prefer plain SQL over procs except where the .NET write path is the contract (`wmsp_WO_N_HeaderInsertUpdate`). [2026-09-10]
- **Windows auth vs SQL auth:** `Trusted_Connection=yes` only works in-process as the logged-in Windows user. Services and Docker use the SQL login `svc_workmate`. [2026-09-10]
- **Alembic vs legacy schema:** never `alembic revision --autogenerate` against the 227 legacy tables (it will try to "fix" them). Migrations are hand-written and only create Workmate-added tables; `version_table_schema="dbo"`. [2026-09-10]
- **PostgreSQL folds unquoted identifiers to lowercase.** `SELECT WO_ID FROM dbo.WO_N_Header` works on PG only if the table was created lowercase (`wo_n_header`, `wo_id`) and the SQL never quotes identifiers. Rule (D-3): PG DDL is lowercase; SQL stays unquoted and mixed-case as today → portable without edits. [2026-09-10]
- **Booleans:** legacy `'Y'/'N'` and `'1'/'0'` char flags are data values; they migrate unchanged; never "fix" them in flight. [2026-09-10]
- **SQLAlchemy 2.1 is rc1** (2026-08-31); the `mssql+mssqlpython` dialect and `greenlet`-optional asyncio land there. Pin `<2.1` until final, then a deliberate upgrade slice. [2026-09-10]

## C. React / Vite / TypeScript

- **`new Date("2026-09-18")` parses as UTC midnight** → the wrong calendar day in negative-offset zones and the wrong hour in NZ. Always `parseISO()` / `differenceInCalendarDays()` from date-fns; never do day math on `Date` objects across the 27 Sep 2026 DST change. `lib/dates.ts` is the only place that touches `Date`. [2026-09-10]
- **`create-tsrouter-app` is deprecated; the entry point is `@tanstack/cli create`.** `--router-only` (file-based Router SPA, no Start) **disables `--add-ons`, `--deployment` and `--template`** — `tanstack-query` and `shadcn` go in by hand afterwards. `--toolchain` values are `biome` or `eslint` only (no `oxlint` on 0.71.0); the `eslint` add-on is ESLint 9 + Prettier and writes `eslint.config.js`, `prettier.config.js`, `.prettierignore`. `--tailwind` is a deprecated no-op. Verify flags on the box with `--list-add-ons --framework React --json` / `--addon-details <id>` before a script relies on them — S0 lost `web/` to a flag that had stopped existing. [2026-09-12, @tanstack/cli 0.71.0]
- **pnpm 12 refuses postinstall scripts and exits non-zero AFTER the add succeeded.** `ERR_PNPM_IGNORED_BUILDS` with the packages already listed under `dependencies:` — a policy failure, not an install failure; read the output before re-running. The CTA template pre-approves builds in `package.json → pnpm.onlyBuiltDependencies`, which pnpm 12 ignores ("no longer read") — that is why the CLI's own `pnpm install` fails. `pnpm approve-builds` writes `pnpm-workspace.yaml` → `allowBuilds:` (pnpm 12's shape); commit it; delete the dead `package.json` field or every pnpm call warns. [2026-09-12, pnpm 12.3.4]
- **Vite env vars must be `VITE_`-prefixed** to reach the browser (`import.meta.env.VITE_API_BASE`). [2026-09-10]
- **Vite 8 = Rolldown.** `@vitejs/plugin-react` 6 dropped Babel; Vite ≤7 is unsupported by it. Plugins that shipped Babel transforms need their Oxc/Rolldown equivalents. [2026-09-10]
- **React 19:** `ref` is a plain prop (`forwardRef` deprecated); StrictMode double-invokes effects in dev — a naive `setInterval` poll fires twice; use TanStack Query `refetchInterval` instead of hand-rolled polling. React Compiler is opt-in through the plugin preset; don't hand-memoise around it. [2026-09-10]
- **React 19.3** (2026-09-09): View Transitions and Fragment refs are stable; useful for the drag/drop card animation later — not in S1. [2026-09-10]
- **TanStack Router file routes** generate `src/routeTree.gen.ts`; the Vite plugin regenerates it on dev/build. Commit it (or generate in CI) — a missing gen file is the classic "routes not found" on a fresh clone. [2026-09-10]
- **TanStack Query:** the query key is what the `@tanstack/react-query` hey-api plugin generates (it carries the query params — `['planner','range',from,to]` from 1.0.0 is superseded, OD-22); `staleTime` > 0 or every mount refetches; `refetchIntervalInBackground: false` to pause the 60 s poll in hidden tabs; optimistic update + rollback in `onMutate/onError` for the drag move; `invalidateQueries` on success. [2026-09-10]
- **The `/range` payload does not scale to a browser window.** 293 KB for one week, **21 MB at the contract maximum of 400 days**, and 363 `workerWeeks` entries on a single week regardless of who has work. The 400-day window is an API capability, not a window the UI may request. **OD-23: `usePlannerRange` refuses anything over `MAX_WINDOW_DAYS = 42` inclusive before fetching** — the oracle's widest window (`windowFor('month')`, 6 rows × 7). Six-month mode (~27 weeks, ~8 MB) needs an API summary shape, not a bigger cap. [2026-09-12]
- **Tailwind v4 is CSS-first:** `@import "tailwindcss";` + `@theme {}` in `index.css`; no `tailwind.config.js` by default; dark mode via `@custom-variant dark`. shadcn/ui components assume v4. The scaffold's `--tailwind` + `--add-ons shadcn` has produced duplicate Tailwind deps — check `package.json` for both `@tailwindcss/vite` and `@tailwindcss/postcss` and keep only `@tailwindcss/vite`. [2026-09-10]
- **shadcn/ui is copied source**, not a dependency. Updating a component = re-running `pnpm dlx shadcn@latest add <n>` and diffing. [2026-09-10]
- **dnd-kit:** wrap the grid in one `DndContext`; `PointerSensor` with `activationConstraint: {distance: 6}` so a click still opens the WO card; one `useDroppable` per day cell with the ISO date as id; `useDraggable` per WO with `wo-<id>`; `DragOverlay` for the moving card; `pointerWithin` collision for grid cells. Classic `@dnd-kit/core` v6 is the stable line; `@dnd-kit/react` 0.5 is the rewrite — later. [2026-09-10]
- **Generated API client** is never hand-edited, never linted, regenerated after every backend contract change, committed. Generator is `@hey-api/openapi-ts` (OD-22); `openapi-typescript` emits types only — rejected. `@hey-api/client-fetch` is **bundled since 0.73** — named in `plugins`, not installed; `output.format`/`output.lint` are deprecated in 0.99 → `postProcess`. **Prettier only in `postProcess`:** the ESLint post-processor runs the project config over vendor code, and `@tanstack/eslint-config` puts 47 house-style errors on it (`TXxx` type-parameter naming, `no-unnecessary-condition`, `no-shadow`) and fails the generation. `eslint.config.js` ignores `src/api/client/**`, `src/routeTree.gen.ts`, `dist/**`. Input is the **committed** `docs/api/openapi_<ver>.json`, not the live URL. [2026-09-12, openapi-ts 0.99.0]

Stub `fetch` with `vi.stubGlobal` and read `input.url` — the stub receives a `Request`, not a string. [2026-09-12]
- **`from` is a legal TypeScript property name** — the third occurrence of the alias resolves harmlessly: `query: { from: string; to: string }` and `RangeData.from`. The pin is the wire, not the name: assert the built URL carries `from=` and never `from_=`. [2026-09-12]
- **`vitest.config.ts` imports `./vite.config.ts` with the extension**, or Vite's native config loader warns and a future major refuses. Keep test settings in `vitest.config.ts` via `mergeConfig` so the router plugin's `vite.config.ts` stays untouched. [2026-09-12, vitest 5.0.0]
- **The scaffold picks majors for you.** `@tanstack/cli` 0.71.0 installed `typescript 6.0.3` against a 5.9.x pin and `eslint 9.39.5` with an EOL warning against a doc that says 10. Read `pnpm ls --depth 0` after every scaffold and decide the pin as a choice, not an accident. **Decided OD-28 (2026-09-12):** TypeScript **6.x** and ESLint **10** are the pins (`@tanstack/eslint-config@0.4.0` peers `^9.0.0 || ^10.0.0`; `pnpm add -D eslint@^10` → 10.10.0, no peer warnings, lint silent before and after). TypeScript **7.0.2** (the native compiler) is published and deliberately not taken. [2026-09-12]
- **`@tanstack/cli`'s `main.tsx` builds its own `createRouter(...)` and never imports `router.tsx`.** The CLI's `getRouter()` is dead code from the first commit. Patch `main.tsx` (that is where `QueryClientProvider` went in S1f) and delete `router.tsx` — or wire `main.tsx` to it; never leave both. [2026-09-12, @tanstack/cli 0.71.0]
- **A route file exports `Route` and nothing else.** A default export or a `VERSION` const in `src/routes/*.tsx` is pulled into the main bundle and the router plugin cannot code-split the route — it warns once per import (eleven times in S1f). With only `Route` exported, `planner-*.js` is its own chunk. The version goes in the header comment; the view logic goes in a props-driven component under `features/` (`PlannerView`), which is also what lets the wire test run without a router. [2026-09-12, @tanstack/router-plugin 1.168]
- **`vitest.config.ts` has no `setupFiles` and no `globals`.** So RTL's auto-`cleanup()` never runs and jest-dom is not installed. Every component test calls `cleanup()` in `afterEach` and asserts on `className` / `style.width` / `textContent`. Adding a setup file later is a deliberate change to every existing test, not a fix. [2026-09-12, vitest 5.0.0]
- **Vite is on port 3000, not 5173** — the scaffold's `dev` script is `vite dev --port 3000`. And Node binds `localhost` to `::1` on Windows while the backend binds `127.0.0.1`, so `Test-NetConnection 127.0.0.1 -Port 3000` says False while Vite is up. A port check tries both stacks (the block is in log 2026-09-12 1.1.0 §5.6); every smoke URL is `:3000`. [2026-09-12]
- **`.chip` needs `flex: none` in a column flex list.** `height: var(--chip-h)` alone lets a flex item shrink; past ~25 chips in one day cell they squash into a smear instead of scrolling. `planner.css` 1.0.1 adds `flex:none` and the list's `overflow:auto` does what it was for. The oracle's `wm-ui.css` carries the same latent bug — KT never had a 106-PM day, RST does (§E). Carry back to Planner 1.8.1. [2026-09-12]
- **A Vite warning prefixed `[Client]` came from a browser tab, not the server.** An old tab's cached module logs through the HMR client and keeps reporting a bug that is already fixed on disk. Close the old tabs before judging a fix by the dev-server console. [2026-09-12]
- **Node 24 vs 26:** stay on 24 LTS until 26 enters LTS (2026-10-28). Corepack is no longer bundled with newer Node lines → install pnpm with winget (`pnpm.pnpm`) or `npm i -g pnpm`, not `corepack enable`. [2026-09-10]
- **Windows line endings:** `.gitattributes` with `* text=auto eol=lf`, Prettier `endOfLine: "lf"`; otherwise ESLint/Prettier fight on every file. Generated JSON written from Python on Windows carries CRLF; git normalises it on commit (warning only). [2026-09-11]

## D. Jython 2.7 → Python 3.13 translation traps (porting `workmate.planner*`)

- **Integer division:** Jython `/` on two ints is floor division. Every `/` in the source was audited to use floats explicitly (`float(dayOfYear - num4) / 7.0`) — keep the `float()`, or use `//` where floor is intended. [2026-09-10]
- **`round()` semantics** differ (§A). [2026-09-10]
- **A 1:1 parity port keeps `'%s' %` behind `# ruff: noqa: UP031`, file-wide.** `UP` is selected and would rewrite every ported message to an f-string — exactly the rewrite the parity contract forbids. A file-wide pragma beats `per-file-ignores` in pyproject: the reason lives next to the code. [2026-09-11]
- **`isinstance(v, str)` no longer lies** — DB strings are `str`, not `unicode`; `basestring` is gone. The `'%s' % v` coercion habit can stay (`_s()`). [2026-09-10]
- **`except:` bare** → `except Exception:`; NQ errors as `java.lang.Exception` are gone; SQLAlchemy raises `sqlalchemy.exc.*` (walk `e.orig` for the pyodbc error, `e.orig.args[1]` has the SQL Server message — the `_err()` twin). [2026-09-10]
- **`system.date.*` → `datetime`/`date`/`zoneinfo`**: `addDays` → `+ timedelta(days=n)`; `isAfter` → `>`; `format(d,'yyyy-MM-dd')` → `d.strftime('%Y-%m-%d')`; `getDayOfYear` → `d.timetuple().tm_yday`; `.NET DayOfWeek` (Sunday=0) → `(d.weekday() + 1) % 7`. Java's lenient `SimpleDateFormat` rolled `2026-02-31` to 3 March; Python's `date.fromisoformat` is calendar-strict and rejects it. The strict behaviour is the right one — pin it with a test so nobody "fixes" it back. [2026-09-11]
- **`system.db.runPrepQuery(sql, params)` → `conn.execute(text(sql), {name: value})`** with named binds; the `?` positional style becomes `:from_d`/`:to_d`. `_rows(ds, cols)` → `[dict(r) for r in result.mappings()]`. [2026-09-10]
- **`system.db.beginTransaction`** → `with engine.begin() as conn:`; the `_tx=None` "caller-owned transaction" pattern becomes a `conn` parameter (tests pass a rolled-back connection). [2026-09-10]
- **A pure function that filters its own list is O(n) per call and O(n²) in a loop.** `hoursFor(wo, labour)` and `assignedFor(wo, labour)` each scan the full list; calling both per WO is fine at KT scale and quadratic on 20 years of RST. Index once by key in the **service** and pass the subset — provably identical output, `rules.py` stays byte-1:1, and a test pins the equivalence. [2026-09-11]
- **Tabs → 4 spaces** (Ruff reformats); keep the function names and dict keys identical so the parity tests map 1:1. [2026-09-10]
- **`dict.items()` sorting** with `key=lambda kv: (-kv[1], kv[0])` still works; `cmp=` does not exist. `sorted(set(...), reverse=…)` fine. [2026-09-10]
- **Module globals as caches** (`_hoursUom`, `_ENGINE_FROZEN`) — fine in one process; with multiple uvicorn workers each worker caches independently (harmless for read-only lookups). [2026-09-10]
- **Gateway-side session dict with 2 h TTL** (planner_chat context) → per-process dict is fine for one worker; multi-worker needs a table or Redis — not in phase 1. [2026-09-10]

## E. Legacy Workmate data truths (carried over — verify on RST before relying)

- WO status codes: R=Request, H=Planned, P=Pending, K=Acknowledged, A=Approved, V=Active, C=Closed, D=Cancelled, F=Deferred; Open = NOT IN ('C','D'). Planner: locked = C/D, confirm = V, engine-frozen = V/C/D.
- PO status codes: P Pending, W Waiting, A Approved, I Issued, R Received, T Part Received, C Completed, X Exported, Q RFQ, D Cancelled.
- `WO_N_Header` (uppercase H): `WO_ID`, `Status`, `Request_Start_Date`/`Request_End_Date` (datetime — full-day span), `Week_No` (numeric `YYYY.WW`), `WO_Type_Flag` ('M' = PM), `Purchase_Order_Flag`; `Priority_Id`, `Progress_Id`, `Duration_In_Hours`, `User_ID_Responsibility` live on `WO_N_Details`; no `User_Id_Assigned` on the header; write proc `wmsp_WO_N_HeaderInsertUpdate`.
- `WO_Status` owns the WO_ID sequence and gates the header — companion row first.
- Completed PMs archive to `WO_C_*`, not `WO_N_*`; labour history = `Trx_Type 'L'` rows in `WO_N_Activity` ∪ `WO_C_Activity`. **`WO_C_Activity` labour can be empty** — don't assume rows exist. [2026-09-11]
- Progress FK rejects 0: None=1, Wait=2, 25%=3, 50%=4, 75%=5, 100%=6.
- `Asset` uses `Direct_Location`, not `Location_Id`.
- `Week_No` is the .NET algorithm (`_netWeekNoAndYear`: Sunday=0 weekday, 8-num2 offset, 53-week rule) — port it exactly, unit-test against known KT values.
- Active domains: `Users.Active` 'Y'/'N'; `User_Skill.Active` '1'/'0' — exclude both '0' and 'N'. Assignable worker = active user with ≥ 1 active skill row.
- **`Priority.Colour` is `#FF8000` on every row at KT — that is KT-only, not a schema truth.** Either way priority renders as a LETTER badge (`Short_Priority_Id`), so the colour is never load-bearing. [2026-09-11]
- **`User_Skill.Hrs_Per_Week` is placeholder data on RST** — mostly `1.0`, some `0.0`, a few real 40s. Capacity percentages computed from it run to four figures. The arithmetic is correct; the input is not. Don't tune the rules to make the numbers look sane — and don't tune the rendering either: OD-25 ports the oracle's `width: min(100, pct)%` with the real pct in the label. Measured on RST: 363 workers = 179 internal + 184 contractors, 46 internal with hours on the standing week 2026-09-14..20, **72** on the June variety week 2026-06-01..07 (OD-24; the loaded-only rail default is OD-26). Top of the table: worker 80 at 2400 %, 1036 at 1700 %, 692 at exactly 1000 % (10 h on 1 h/wk — the fixture's row). [2026-09-12]
- **RST priorities are `P1`…`P6` and `N/A`, not the A–D letters the oracle's `.pri.A/B/C/D` colour rules key on.** Every badge renders in the base muted style, three characters wide at most — parity, not a defect. Colouring by `Priority.sortOrder` / id departs from the oracle and needs an OD (log 2026-09-12 1.1.0 §8.19). [2026-09-12]
- **`initials` breaks on names with parentheses:** `JP Paalvast (TS)` → `J(`; also `T(`, `M(`, `C(` on the chips and the rail. That is the backend `initialsOf` port, not the UI — a backend item with its own test (open item 21). [2026-09-12]
- **106 PMs on one day is normal on RST** (Mon 14 Sep 2026; Mon 3 Aug 2026 holds 181 done) — twenty years of weekly PMs land on the same weekday. Anything that renders a day must scroll, cap or summarise: the oracle's `+N more` cap and the list's `overflow:auto` are load-bearing, and so is `.chip{flex:none}` (§C). [2026-09-12]
- **`Users.User_Id` is NUMERIC** → arrives as `Decimal` in Python. `User_Id = 1` is `SYS_USER` / "System User" — the right dev actor precisely because it is not a real person. [2026-09-11]
- **Triggers on RST are PO-only.** The `OUTPUT INSERTED.*` caution (§B) still stands for portability, but the specific hazard is confined to the PO tables here. [2026-09-11]
- Internal team = modal supplier among active skill rows OR `Supplier.Internal_Dept IN ('1','Y')` — never a hard-coded supplier id (KT's happened to be 11).
- Labour UOM = `Unit_of_Measure.LRStd = 'Y'` row resolved at runtime — never a hard-coded 9. RST resolves to **12 LABOUR HOURS**; assert the resolution logic, not the number, so the test survives a swap to the KT copy.
- `WO_N_Resource` labour row: `Resource_Type 'L'`, `Res_Id = MAX+1 in-tx`, `Res_Date` = the legacy "User Planned Date", `Supplier_Id` from the person's skill row, `Planned_Qty` hours, `Planned_Unit_Cost` rate.

## F. The box — AzztecDev (Windows 11, 32 GB, local SQL Server + Docker Desktop + Node + a browser)

- **Check the box before the code.** On any "it's slow": free memory and the top-5 processes by working set first, pasted verbatim, before a single hypothesis. The S1f session spent four hours on DMVs and request timing while Task Manager had the answer — Docker Desktop's VM (`com.docker.backend`) at **45 GB committed / 19 GB resident on a 32 GB box**, SQL Server squeezed to a **0.1 GB** working set, every `/range` two minutes. The 16:40 pool-exhaustion 500 (`QueuePool limit of size 5 overflow 10 reached, connection timed out`) was the first *symptom*: twelve concurrent two-minute queries is exactly what exhausts a 15-connection pool. No file, no SQL, no lock, no blocking session was involved. [2026-09-12]
- **SQL Server `max server memory` is uncapped** on AzztecDev (`2147483647`; `@@SERVERNAME` AzztecDev, Standard Developer Edition 64-bit 17.0.1000.7, `min server memory` 16 MB). Default "take everything" loses the fight to a ballooning Docker VM and runs from the page file. Cap it at **8 GB** with `sp_configure` in SSMS under a sysadmin login — `svc_workmate` cannot (open item 16). Do it before the next smoke. [2026-09-12]
- **Docker Desktop needs a memory cap** before it runs alongside SQL Server again — Settings → Resources, or `.wslconfig` `memory=`. Until it has one, Docker stays off; the compose file waits (open item 17). Recovery when it happens anyway: kill Docker Desktop and its service, `wsl --shutdown`; memory fell 29.6 → 9.5 GB in ~60 s, the first query after paid ~40 s of SQL re-warming from the page file, then 100–300 ms again. [2026-09-12]
- **`sys.configurations.value_in_use` is `sql_variant`** — pyodbc refuses it (`ODBC SQL type -16 is not yet supported`). `CAST(value_in_use AS int)`. [2026-09-12]
- **`svc_workmate` has `VIEW SERVER STATE` but not `VIEW SERVER PERFORMANCE STATE`:** `sys.dm_exec_requests` / `sys.dm_exec_sessions` answer, `sys.dm_os_process_memory` is denied. The memory answer comes from Task Manager or `Get-Process` sorted by `WorkingSet64`, not from a DMV. [2026-09-12]
- **Healthy `/range` on RST is 70–700 ms** (standing week 273 rows 100–400 ms; the 42-day August month, 3784 rows, ~500 ms). Anything over 2 s is the box, not the code — go to the first line of this section. The 5 s / 15 s outliers seen right after a memory recovery were re-warming; if they recur with Docker down they are real (open item 23). [2026-09-12]
- The diagnostic helpers from the incident (`dbdiag.py` — requests / open transactions / sessions by program; `sqlmem.py` — configured limits + DMVs) live in `%TEMP%`, not the repo. Read-only, on the backend's own `build_url`. Worth a `scripts/` home with a version header the second time they are needed. [2026-09-12]
