### 5.7 `pin_table_exists` is not cached — the flip needed no restart

The `[F]` lines show `pinTable=False` at 17:54:09 and `True` at 17:55:10 with no reload between them. Reading `repo.py` 1.1.0: `pin_table_exists(conn)` is a bare `db.table_exists(conn, PIN_TABLE)`, and `clear_caches()` only drops the per-engine UOM cache — the only two caches in the module are `_uom_by_engine` and SQLAlchemy's per-connection reflection. So the migration landing between two polls is the entire explanation. I had guessed a TTL cache before reading the module; there isn't one, and the truth is simpler. Worth knowing for S2: a schema change is visible to a running server on the next request, with no restart and no cache to clear.

## 6. Mistakes caught this session

### 6.1 Ruff called `alembic` first-party because we created a directory with that name

`I001` on `env.py`: `backend/alembic/` on disk makes ruff's isort classify the *package* as first-party, so it wanted `from alembic import context` regrouped. Python itself has no such problem — a regular package on `sys.path` beats a namespace directory. The wrong fix was reordering imports to satisfy a misclassification; the right one was telling ruff the truth, `known-third-party = ["alembic"]` in `pyproject` 1.0.1. A lint rule disagreeing with the interpreter is a configuration fact, not a code smell.

### 6.2 `SIM300` on an assertion that was not a Yoda condition

`assert gen.SKIP_INDEXES == frozenset({...})` — ruff reads the bare name as the constant and the literal as the variable, and suggests swapping them. Rewritten as a membership plus a length check, which reads better anyway. Not worth an `# noqa`.

### 6.3 Two predictions wrong, both mine, both arithmetic

- **`167 passed` predicted, `169` observed.** 154 + 15 = 169; I carried N=13 from the 1.0.0 draft of the test file into the prediction after the 1.0.1 bump added two tests. The suite was right; the prediction was stale.
- **`new_cols 15` predicted, `18` observed.** My *verification query* counts column names across the nine tables and MSSQL matches case-insensitively, so it also counted the three pre-existing legacy `User_Id_Created_By` stamps from §4.1 — 15 new + 3 old. The query was loose, not the migration; the real check is the per-pair assertion in `test_kt_uplift`, which passed. A verification query that can be satisfied by data it was not asking about is a bad verification query.

Both are the predict-then-read rule working as designed: a wrong prediction that gets caught and written down beats a number read without one.

### 6.4 A card that project knowledge will not accept

`Azztec_SaaS_alembic_script_mako_v1_0_0.mako` offered Download and Print but **"Add to project" greyed out** — the extension is not on the allowed list. Shipped a byte-identical `.txt` twin for project knowledge; the disk copy keeps `script.py.mako` because Alembic requires that name. New rule: a card whose target filename has an unusual extension needs a `.txt` twin for PK, decided when the card is cut, not after.

### 6.5 A block that printed an error and still worked

`Get-Item $map.Values | Format-List` — PowerShell passed the whole collection as one path string and threw `PathNotFound`. The copies had already happened; only the size printout was lost. Fixed by looping. `Format-List` on a collection of paths is not the same shape as `Format-List` on one.

## 7. Patterns confirmed

- **`--dry-run` as the default verb, not a flag you remember.** The generator writes nothing unless told to, so the first run of a DDL generator is always a read. It paid for itself immediately (§4.3).
- **Generate, then diff the generated file against its source.** `test_committed_migration_matches_the_kt_catalog` re-reads the oracle and asserts byte equality with what is committed. A hand-edit to the migration or a change at KT is now a red test, not a discovery six weeks later.
- **Skip loudly, never pass quietly.** Both DB halves skip with the reason in the message when their database is unreachable. The visible `2 skipped` is what proved the oracle gate ran.
- **Verify the parents before adding the FK.** Three one-line catalog reads turned "KT has these keys so RST must" into a fact. This is the same habit as §4.1's collision check: the dev database is not the oracle until measured.
- **Fix a wrong rendering as a new version; never commit a file you know is wrong.** Generator 1.0.0 → 1.0.1 mid-slice, with the two ODs raised and signed before the rebuild (OD-46a, OD-46b).
- The `Test-Path`-first Downloads block held again — fifth session running, eight cards plus the spec, zero losses.
