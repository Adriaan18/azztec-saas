## 1. What this project is

Workmate is being rebuilt from Ignition Perspective (the "Ignition Edition", live at KT) into a standalone product: **FastAPI backend + React frontend**, PostgreSQL as the target database, MSSQL as the development reality. Development runs against **`dbWorkmate` on the local SQL Server, restored from the Red Stag Timber (RST) Workmate database — ~20 years of real CMMS data**. The first function built is the **Planner** (P-PLN1), ported 1:1 from the live Ignition planner (same JSON contract, same pure rules).

The AI brain (`workmate-ai`, Layers 3–8) is the same service for both editions — see `Workmate_AI_Architecture_v1_2.md`.

**Where the build is (2026-11-07, close of the DP1 + DP2 session):** three of the four slices for the **Redstag test drop, wanted Monday 2026-11-09**, shipped, each smoked on a fresh RST restore and pushed. The brief (log 11-07 §0): the Planner **with moves**, sign-in from **Workmate's own users and rights**, a schema script their DBA re-runs after every restore (they test, drop the database and restore production again), a deploy kit, a test laptop over the weekend and then **Andrew's** approval.

**DP1** (`06618ae`, tag `dp1-schema-1.0.0`, OD-90…OD-95): `scripts/deploy_sql.py` **1.0.1** renders **`deploy/sql/azztec_schema.sql`** from every migration's `MSSQL` step list. It is one idempotent T-SQL file their DBA runs in SSMS after each restore: guarded steps that print `created` / `present` and ask the catalog again after each `EXEC`; the version stamped to the head; the app's database user re-created from `@AppLogin` with `db_datareader` and `db_datawriter` only; a `NOEXEC` refusal in any database that isn't Workmate's; and a last line of `AZZTEC SCHEMA OK` or `INCOMPLETE`. A test fails if the committed file differs from a fresh render. Smoked on **`dbWorkmate_DP1_Test`**, a pristine restore of `C:\dev\backups\RST_Workmate.bak` (RSTSQL01, 26 Aug): 43 created then 44 present, 245 objects added and nothing else touched, zero catalog differences against the alembic-built schema, the refusal holding in `master` with and without `sqlcmd -b`.

**DP2a** (`1bc2f0a`, tag `dp2a-auth-1.0.0`, OD-96…OD-103, app **0.6.0**): people sign in with their **Workmate.NET login and password**, verified against Workmate's own MD5-20 store and never copied. Rights are the Ignition model ported as pure rules: the lowest group level, the page's menu tag (Planner = Schedulex, Option A), the more restrictive of the two. `app/auth/` **1.0.0** (`rules` `sql` `repo` `service` `schemas` `router`) answers `POST /auth/signin`, `POST /auth/signout` and `GET /auth/me`. The session is server-side: a 256-bit `azztec_session` cookie (`HttpOnly; Secure; SameSite=Strict`), only its SHA-256 in `Auth_Session`, 12 h absolute and 4 h idle. Refusals come only after the password is proved (`SYS_USER`, a default password including the login id, no group, reset due); lockout is 5 per login / 20 per address in 15 minutes; every attempt is one `Auth_Event` row, never a password. `deps.py` **1.2.0** resolves one `Principal` per request; `require(page, right)` sits on the Planner and WOMaint routers, `_diag` is dev-only and then administrator-only, and every non-GET needs `X-Azztec-Request: 1`. **No request runs as `WORKMATE_DEV_USER_ID` any more** (OD-103). Migration **`0002_auth_sessions`** (hand-written in the step-list shape) adds the two tables; the client script is re-rendered to head `0002` (47 steps). Contract `openapi_0_6_0.json`, 12 paths.

## 4. Standing rules (one screen)

1. **Sequence:** audit → spec → 🤙 → one slice → versioned raw file(s) as Download cards → smoke → raw log → next. Never run ahead of 🤙. The audit may cut the scope it was handed; an unsigned dependency is the next audit's first line, not this build's next step.
2. **Version everything, never overwrite.** Delivered filename carries `_vX_Y_Z`; the file carries `__version__` / a header (route files: header only) — **and the two are compared mechanically before any card is emitted** (two S1h files had 1.1.0 in the header and 1.0.0 in the constant; a script caught it, reading did not). Tag the version that **shipped**, not the one the spec predicted. A withdrawn decision keeps its ID, struck through, with the reason (OD-32); a delegated decision is recorded as delegated, not signed (OD-35). **Format-clean before commit:** **`ruff format --check .` is its own gate in every smoke**, beside `ruff check` — `ruff check` cannot catch what `ruff format` fixes (E501 is ignored in `pyproject`). Twice now: S1h shipped `router.py` one character over `line-length = 110` past a check-only smoke (fixed as `router.py` 1.1.1, format-only), and D1a shipped five reflows in `main.py` the same way (found by W1a's smoke, fixed as `main.py` card 1.0.8, format-only, app version unchanged). Both flagged before they were built — a knowingly false header is never the price of a scope line. **Fix a wrong rendering as a new version — never commit a file you know is wrong** (the S1j generator went 1.0.0 → 1.0.1 mid-slice, OD-46a / OD-46b raised and signed first; the tag is the version that shipped, `1.0.1`).
3. **Raw source files only**, one per Download card, via `present_files`. No inline code dumps, no zips. Each card states **PK: add / replaces `<version>`**. Save every card before the block that copies it runs — Downloads is not a staging area, and it has now eaten a deliverable in **three** consecutive sessions; every block that copies from Downloads starts with `Test-Path` on each source and prints it — that block held on fourteen cards and the spec in the S1i session and on eight cards and the spec in S1j — keep it. A card with an extension project knowledge refuses (`.mako`) ships its `.txt` twin when it is cut.
4. **Pair rule:** every library slice ships with its tests. Pure rules are tested with zero DB — and a zero-DB test must actually be zero-DB; zero-network means the stubbed fetch is asserted never called.
5. **`DRY_RUN = True` first** on anything that writes — `--dry-run` is the default verb, not a flag you remember: the S1j generator's first run was a read and caught two wrong renderings, and `alembic upgrade head --sql` is a migration's dry run; Marker Law (residue = 0) on anything touching real data — the RST DB is real data even in dev. S1j wrote DDL to it (`0001`, zero rows); S2 is the first slice that writes **data** to it. `dbWorkmate_KT` is READ_ONLY and stays that way; `dbWorkmate_KT_RFID` is the writable KT copy for Ignition RFID work, outside this build, and **carry-backs to KT are DDL scripts, never files** (item 40).
6. **Fact-check before build:** confirm columns / codes / flags against the schema CSVs and the DB. Never re-emit a file you have not read — CLI-written files, generated code, the oracle's strings and **column names** included. **A decision about data is blocked on reading the table, not on 🤙** — the pasted rows go in the spec before it is signed. Say "the API doesn't send it", never "it isn't there". **The database says what exists, the gateway export says what is used** — grep a candidate against the export before calling it load-bearing. **Verify FK parents on the target** before adding the FK — a one-line catalog read, not "KT has these keys". **And a verification query must not be satisfiable by data it was not asking about** (`new_cols` read 18 for 15 added — MSSQL matched legacy stamps case-insensitively; the per-pair test was the gate).
7. **Dialect-portable SQL** (COALESCE / CURRENT_TIMESTAMP / CONCAT / OFFSET-FETCH / `dbo.` / `-- PG-CONVERT:` tags). The CI gate greps the whole file — describe banned tokens, never spell them.
8. **Forensic diagnostics** on every request outcome: [F] what happened, [G] why blocked, [E] crash — one `diag.log()` seam, wired by `diag.configure()`. Assert **emission**, not the call.
9. **Check the box before the code.** On any "it's slow": free memory and the top-5 processes by working set first, verbatim. Healthy `/range` is 70–700 ms; over 2 s is the box (Landmines §F) — and a box that reads clean is still the box for hours if SQL Server has not been **restarted** since a memory squeeze: free RAM is not a recovered buffer pool (item 30, closed). Restart, then measure; attribute what remains with `dm_exec_query_stats` / `dm_exec_session_wait_stats` (Architecture §3.3).
10. **Comms:** short, direct, NZ-casual. Console output pasted verbatim before proceeding — and wait for the prompt before pasting the next block.
