## 1. Purpose

Port the live KT Planner to FastAPI + React **behaviour-for-behaviour**, running first against the RST data, keeping the
JSON contract byte-compatible so (a) the Ignition planner is the parity oracle and (b) `Planner_v1_8_1.html` can be pointed at
the new API as a smoke test — which is why the `/range` envelope keeps `ok`, `apiVersion`, `actor`, `ms` (OD-14). Genuine
Ignition parity (`scripts/parity_range.py`) is **no longer blocked**: the KT database is on the dev instance as `dbWorkmate_KT`,
read-only (2026-09-13; open item 26 reclassified) — the script itself is unbuilt and `svc_workmate` has no user in the copy yet.
What S1a–S1h claim is still wire-level contract correctness and screenshot-level behaviour parity on RST — with one registered departure: `workers[].initials` will diff against the Ignition oracle on roughly 300 bracketed RST names (OD-35), and the parity script carries that as an **expected** diff. The planner was deliberately built for this: everything the UI shows is assembled in
`workmate.planner` from pure functions over plain dicts; `planner_api.route()` is a pure request→response function;
`planner_chat.parse()` is the LLM seam.

## 3. The JSON contract (unchanged keys)

`GET /api/v1/planner/range?from=YYYY-MM-DD&to=YYYY-MM-DD` → `RangeData` — the Ignition `rangeData` keys below **plus the flat envelope** (OD-14, 2026-09-11): `ok: true`, `apiVersion` (`router.__version__`), `actor`, `ms`. `gate` is dropped (retired with the sid gate). `Planner_v1_8_1.html` reads all four. Errors are the flat app-wide body `{ok:false, code, message, rid}` (OD-15); a bad window is `service.WindowError` with `code='BAD_WINDOW'`, caught by type in the router → 400 (OD-16). The `from` key needs `Field(alias="from")` on the model **and** `Query(alias="from")` on the parameter, and the generated TS client must emit `from=` on the wire — three places, each pinned by a test (Landmines §A/§C).

| Key | Type | Notes |
|-----|------|-------|
| `ok`, `apiVersion`, `actor`, `ms` | bool, str, int, int | the envelope (OD-14) — not Ignition `rangeData` keys, but the same wire the oracle UI reads. `apiVersion` is `router.__version__` — **1.1.1 since S1i**: 1.1.0 at S1h for a field added inside a sub-model, because it is the only contract signal a generated client sees (OD-37); 1.1.1 a format-only re-wrap (fix, no contract change). The exported document is `docs/api/openapi_0_4_0.json`, named from `main.__version__` 0.4.0 (OD-38) |
| `from`, `to`, `today` | `YYYY-MM-DD` | window inclusive; 400 `BAD_WINDOW` on bad window or > 400 days; `today` resolved in `WORKMATE_TZ` (OD-6). The UI never asks for more than 42 inclusive days (OD-23) — the 400-day ceiling is an API capability, not a window the UI may request |
| `wos[]` | WO dict | `id, sid, title, status, statusTitle, type, cat (DONE/PM/REQ/WO), start, startTime (HH:mm or ''), end, days, weekNo, prog, priId, pri, estimate, resp, asset, assetTitle, loc, locTitle, hasPO, engineOwned, pinned, pinnedOn, engineDate, locked, movable, hrs, hrsSrc ('labour'/'estimate'/''), assigned[userId]` |
| `labour[]` | labour row dict | `resId, woId, userId, hours, rate, note, date, skillId, skillTitle, uomId` |
| `workers[]` | worker dict | `id, sid, name, initials, skills[{id,title,sysId,hrsPerWeek,supplierId}], hrsPerWeek, teamId, team, internal` — internal first, then by name |
| `teams[]` | team dict | `id, short, name, internal, users` — internal first |
| `priorities[]` | `{id, short, title, colour}` | active, by `Sort_Sequence, Priority_Id` (OD-11). **`colour` since S1h** (`sql.py` / `repo.py` / `schemas.py` 1.1.0): the column **as stored, `''` for NULL, validated nowhere in the backend** — no enum, no hex check, no default, because a backend default would be indistinguishable from real data downstream (OD-36); `Colour` is `varchar(255) NULL` free text on both databases, so the renderer guards before painting — **done, S1i (2026-09-14):** `priBadgeMap` paints a row only if `colour` passes `^#[0-9A-Fa-f]{6}$` and the payload carries ≥ 2 distinct usable colours case-folded (OD-39), text colour by WCAG contrast against `#2b2b2b` / `#ffffff` (OD-40), inline at both badge sites (OD-41). | `weeks[]` | `{weekStart, planned, unknown, count, capacity, pct}` | Mon–Sun weeks touching the window; capacity = internal workers' `hrsPerWeek` |
| `load` | `{"<userId>": hours}` | key `"0"` = unassigned |
| `counts` | `{wo, pm, done, total}` | the parity numbers |
| `pinTable` | bool | `WO_N_Plan` exists — `False` on RST today; the uplift (item 32) or S3's migration 0002 flips it, which is uplift-audit question 3 |
| `workerWeeks` | `{"<userId>": [{weekStart, planned, capacity, pct, flag (over/ok/under/empty)}]}` | flag thresholds: over >100, ok 80–100, under 1–79 with capacity, empty 0. | `uomHours` | int | the `LRStd` UOM id — resolved at runtime (RST: 12 LABOUR HOURS); assert the resolution, not the number |
| `libVersion` | str | `rules.__version__` — a new lineage starting at 1.0.0 with `PORTED_FROM = "workmate.planner 1.3.1"` (OD-10), **1.1.0 since S1h** (OD-35 changes the value of a contract field on most bracketed rows — more than a patch, OD-37); `PORTED_FROM` stays 1.3.1, the departure is the record; the S6 `t_versions` port asserts `PORTED_FROM`, not `>= '1.3.1'` |

Write results keep the Ignition dict shapes (`{ok, code, message, sid, preview?, undo?, …}`).

## 5. Rules that must survive untouched

- `moveRules`: refuse `LOCKED_STATUS` (C/D), `ENGINE_OWNED` (PM the engine owns, no pin table), `NO_START`, `BAD_DATE`, `NO_CHANGE`; confirm reasons `PAST`, `ACTIVE` (V), `SPAN` (multi-day), `LABOUR_MULTI`; `willPin` / `willUnpin` / `pinnedAfter`.
- `moveWO` transaction: header start/end shifted by the civil-day delta (time of day kept, NULL end stays NULL), `Week_No = weekNo(newStart)`, subtasks shifted per row in collision-safe order (descending dates when delta > 0), `WO_N_Resource.Res_Date` shifted, `WO_Event_History` 'Rescheduled' + per-field 'Update' rows in the clsSimpleComparer format, `Source_Form='Planner'`; `expectStartIso` optimistic lock; every write returns a dict, never raises past the service boundary; `dry_run=True` default. The pin row it writes (`WO_N_Plan`) has a read lifecycle now, not an invented one: one row per WO that persists, `Pinned` flips, `Prev_Start` is undo's target, `Note` reads `Planner move <from> -> <to>` (KT Schema Delta §4.1).
- `estimateRules`: 0 ≤ h ≤ 1000, needs a `WO_N_Details` row.
- `labourRules`: active user, ≥1 active skill row, 0 < h ≤ 500, `Res_Date` defaults to WO start; `Res_Id = MAX+1` in-tx; UOM = `LRStd` row; `Supplier_Id` from the skill row.
- `setCapacity`: 0..168 on ONE `User_Skill` row (`Sys_User_Skill_Id`).
- `civilDays`: pure calendar arithmetic; DST test 17↔29 Sep 2026 = ±12.
- `initialsOf`: **departs from the oracle — OD-35** (S1h, `rules.py` 1.1.0). The oracle failed on bracketed names two ways: one-word brackets visibly (`JP Paalvast (TS)` → `J(`), multi-word brackets silently (`Adam Donald (Max Edkins)` → `AE` — the wrong person's initials, looking right). `_nameForInitials` removes bracketed segments (unbalanced `(` takes the rest, a bare `)` is dropped) before the unchanged first-and-last pick; the `EXT-` strip, the `1 < len(s) <= 4` short-id bound and the `s[:3]` fallback are untouched. **Item 35 remains, by design:** a trailing role token still wins the second letter (`Andrew Hornby R2 (Max Edkins)` → `AR`), pinned by a test that asserts the wrong value on purpose until a site-specific token list is decided. Item 21 closed.
- Autopilot guardrails (S5): no PMs, priority A/B only, ≤ `PLANNER_AUTOPILOT_MAX_WEEKS` pull, ≤ `PLANNER_AUTOPILOT_MAX_MOVES`/night, never into the past, every move carries its undo. **RST has no A/B priorities** — its domain is fourteen rows (`P1`…`P6`, `ST`, `T`, `W`, `WK-END`, `SHUT`, `P2S`, `N/A`, `REQUEST`; Landmines §E); KT's is exactly `A`/`B`/`C`/`D` (`dbWorkmate_KT`, 2026-09-13), which is what the guardrail was written against. The S5 audit maps the guardrail onto RST's domain before it runs there.

**Deliberate deviations, all signed and documented in-file** (the parity tests map around them): `round()` half-to-even (OD-8); `labourRules` returns `resDate` as a `datetime.date`, no ISO twin (OD-9); `UOM_MODAL` / `_PRIORITY_SQL` tie-breaks (OD-11); `WindowError` by type instead of string matching (OD-16); `hoursFor`/`assignedFor` fed a pre-indexed subset from the service instead of scanning the full list per call — provably identical output, `rules.py` byte-1:1, equivalence pinned by a test (Landmines §D); `'%s' %` kept behind a file-wide `# ruff: noqa: UP031`; `initialsOf` strips bracketed segments (OD-35, the one departure that changes a contract value — registered as an expected parity diff). Two oracle quirks kept on purpose: `chipTitle` on a closed WO carries the PM "engine owned" line because `locked` covers C/D — parity, pinned by `rules.test.ts`; and the UI's chrome says only what is true here (OD-34) — the hint, the rail row title and the disabled `Open` are the oracle's strings edited only where the oracle's text describes a feature this build does not have.
