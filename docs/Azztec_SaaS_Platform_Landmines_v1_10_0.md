**File:** Azztec_SaaS_Platform_Landmines_v1_10_0.md · **Version:** 1.10.0 · **Date:** 2026-09-19 · **Author:** Adriaan
**Status:** Active. One lesson per line; verified date in brackets; platform claims older than a major version bump get re-verified.
**Lineage:** the Ignition-era `Workmate_Knowledge_Journal` / `Workmate_Perspective_Rules` landmines that still bite are carried in §E. §F is the dev box itself — read it first on any "it's slow", and read its `/workorders` band and its buffer-pool line before calling a read slow. §B's `.bak` / `sqlcmd` / cross-database / one-way-door / catalog-DDL set (everything from the `sqlcmd -E` line down) is read before touching either KT copy or generating DDL from a catalog. §A's `ruff format --check` line before assuming `ruff check` caught anything, and its isort line before reordering an import a lint rule disliked. **§E before any WOMaint work** — the Progress domain, the details orphans, the archive's size and what `Server_Name` / `Source_Form` actually hold are all RST facts that differ from KT. §F's last line before assuming a schema change needs a restart.

## A. Python / FastAPI

- **Never do DB I/O inside `async def`.** pyodbc is synchronous; a blocking call in an `async def` route stalls the whole event loop. Use plain `def` routes (FastAPI runs them in anyio's threadpool, default 40 threads) or `run_in_threadpool`. Async comes back only at PG-only with `psycopg` async. [2026-09-10]
- **A logger with no handler and no level is silent for INFO and leaks ERROR to stderr.** `logging.getLogger("x")` inherits root's WARNING, so `INFO` records die at the **level check** before any handler would be consulted, and `ERROR` records escape through `logging.lastResort` — a WARNING-level stderr handler with no formatter. uvicorn's `LOGGING_CONFIG` configures the `uvicorn*` loggers only; it has no `root` key, so nothing fills the gap. A library logger needs a **level and a handler**, set by the application. [2026-09-11]
- **`Logger.hasHandlers()` is useless as a "am I wired?" guard.** It walks ancestors, so under pytest the caplog handler on root satisfies it — the check passes in the suite while the dev console stays silent. Test the specific handler you attached, by name. [2026-09-11]
- **A `StreamHandler` binds its stream object at construction, and pytest moves `sys.stdout` twice.** The default `--capture=fd` is not only an fd redirect: its `SysCapture` half replaces `sys.stdout`, and the `capfd` fixture replaces it **again** on entry. A handler built before the fixture keeps writing to the previous object — the line shows up in the report's "Captured stdout call" section while `capfd.readouterr()` comes back empty. Resolve the stream at **emit** time with a `stream` property, exactly as the stdlib's own `logging._StderrHandler` does. capfd is the right reader; it is not a way around construction-time binding. [2026-09-11]
- **`pytest -q` on top of `addopts = "-q"` deletes the count line.** `pyproject.toml` (line 49) already sets `addopts = "-q"`; a second `-q` on the command line makes pytest quiet enough to drop the `N passed, M warnings in …` summary entirely. Three sessions blamed the pipe — `Select-Object -Last 3`, then `-Last 6`, then `Tee-Object`. Run plain `uv run pytest`, read the count, gate on `$LASTEXITCODE` — and the exit code was the real gate all along. **The same family, one session later:** `pnpm test`'s summary is box-drawn and ANSI-coloured, so `Select-String "Test Files|Tests "` matched nothing, printed blank and looked exactly like a clean run. Run both suites bare; pipe only when the exact output text is already known. [2026-09-13]
- **A catch-all route under an API prefix defeats Starlette's 405.** `Router.app` collects a `Match.PARTIAL` for a real route with a wrong method but only falls back to it when **no** route returns `Match.FULL`. A later `/api/{rest:path}` full-matches on path and wins, turning `POST /planner/range` into a 404. Fix missing-route behaviour at the mount, never with a catch-all. [2026-09-11]
- **`app.frontend()` on a missing `dist/` raises at request time, not at mount.** `RuntimeError: StaticFiles directory '…' does not exist` surfaces as a **500**, so any `/api/...` miss depends on the SPA mount being healthy. Mount conditionally on `dist/index.html` existing; the miss then reaches the app's `StarletteHTTPException` handler as a proper JSON 404. [2026-09-11]
- **`app.frontend()` fallback** serves `index.html` only for `GET`/`HEAD` with `Accept: text/html`; missing JS/CSS still 404; `POST` to an SPA path is 404. Keep the API under `/api/v1` so SPA routes never collide with path operations (path operations always win anyway). `check_dir="auto"` errors on a missing `dist/` unless `FASTAPI_ENV=development` (`fastapi dev` sets it). [2026-09-10]
- **`fastapi dev` imports the app module twice** — once in the reloader parent to resolve the import string, once in the watchfiles child. Anything at module scope, including `app = create_app()`, runs in both processes. Keep `create_app()` free of side effects beyond logging, or every boot double-writes. [2026-09-11]
- **`from` is a Python keyword and the trap bites twice.** A contract key `from` needs `Field(alias="from")` on the model **and** `Query(alias="from")` on the route parameter — two independent declarations, either of which can regress alone. Assert both: the runtime body *and* the published OpenAPI schema. It will bite a third time in the generated TS client. [2026-09-11]
- **`/health` must read `__version__`, never a literal.** A hardcoded version string in the health payload is stale the moment the module bumps, which is precisely the lie the bump rule exists to prevent. Pin it with a test that compares the payload to the modules' own constants. [2026-09-11]
- **Ruff config bans two habits from the start:** `%`-formatting (UP031) and `Depends()` in an argument default (B008). Write f-strings and `Annotated[T, Depends(...)]` in the first draft — retrofitting them is a version bump with no behaviour change. Exception: a file under a 1:1 parity contract keeps `'%s' %` behind a file-wide `# ruff: noqa: UP031` (see §D). [2026-09-11]
- **The CI dialect gate greps the whole `sql.py` file**, docstrings and comments included. A banned token spelled out in prose fails CI while a statement-only unit test passes. Make the test read exactly what the gate reads. [2026-09-11]
- **`ruff format --check .` is its own gate, and `ruff check` cannot see what it catches.** `pyproject` has `[tool.ruff.lint] ignore = ["E501"]`, so a line over `line-length = 110` passes `ruff check` indefinitely and only `ruff format` re-wraps it. **Twice, three days apart, both on inherited lines:** S1h's smoke ran `ruff check` on its seven files and no format pass, `router.py` went into the repo at `5443ac1` with a 111-character decorator, and the S1i smoke's format pass reported it a session later as a fourteenth modified file (`router.py` 1.1.1, format-only); then D1a's smoke did the same and left **five** reflows in `main.py` — `SLOW_MS`, a missing blank line before `Conn`, the diag-wired call, the `INTERNAL` `JSONResponse`, the `dbName` conditional — which W1a's smoke found on lines nobody had touched that slice (`main.py` card 1.0.8, format-only, app version unchanged because the token stream is identical). **Run it repo-wide every slice, not on the files the slice touched** — the drift is always in code that already shipped. Use `--check` (report, then ship a card) rather than a bare `ruff format`, which edits the tree and leaves the project-knowledge card stale. [2026-09-11; E501 2026-09-14; second occurrence 2026-09-19]
- **Ruff's isort calls a package first-party when a directory in the repo shares its name.** Creating `backend/alembic/` (the migration scaffold) made ruff classify the *package* `alembic` as first-party and raise `I001` on `from alembic import context` in `env.py`; Python itself has no such confusion — a regular package on `sys.path` beats a namespace directory. The fix is telling ruff the truth, `[tool.ruff.lint.isort] known-third-party = ["alembic"]` (`pyproject` 1.0.1), never reordering imports to satisfy a misclassification. A lint rule disagreeing with the interpreter is a configuration fact, not a code smell. [2026-09-14]
- **`SIM300` fires on `assert MODULE.CONSTANT == {literal}`** — ruff reads the bare name as the constant and the literal as the variable and asks for a swap. Rewrite as a membership check plus a length check; not worth a `# noqa`. **Same rule, subset form:** `assert CONSTANT <= set(x)` is a Yoda condition too — write `set(x) >= CONSTANT` (W1a's contract test, caught at the smoke). [2026-09-14; subset form 2026-09-19]
- **Dependencies with `yield` and BackgroundTasks:** the post-`yield` lifecycle has changed across releases (0.106, later 0.118-era refinements). Rule: a background task opens its **own** connection; never reuse the request's yielded session in a task. [2026-09-10]
- **FastAPI 0.137.0 refactored routers** — `router.routes` is now a tree of intermediate objects, not a flat list. Anything that iterates `router.routes` (custom OpenAPI hacks, route listing, contract tests) breaks. Use `app.openapi()` or `iter_route_contexts()` instead. [2026-09-10]
- **`fastapi[standard]` pulls in `fastapi-cloud-cli`**; use `fastapi[standard-no-fastapi-cloud-cli]` if you don't want the `fastapi login/deploy` commands. [2026-09-10]
- **Pydantic v2 serialises `Decimal` as a JSON string.** MSSQL `numeric` columns arrive as `Decimal` from pyodbc → the planner contract expects numbers → coerce with the `_i()`/`_f()` twins in the row mapper before building models, or declare fields `float`. [2026-09-10]
- **Naive datetimes.** MSSQL `datetime` comes back naive; the contract wants `yyyy-MM-dd` strings (`iso()`) and `HH:mm` (`timeOf()`). Format explicitly in the mapper; never let Pydantic emit `2026-09-18T00:00:00`. [2026-09-10]
- **Windows has no tz database.** `ZoneInfo("Pacific/Auckland")` raises `ZoneInfoNotFoundError` unless the `tzdata` wheel is installed. It is in the pyproject; don't remove it. [2026-09-10]
- **DST day arithmetic:** the Ignition bug (`system.date.daysBetween` asymmetric across 27 Sep 2026) is reproducible in Python if you subtract aware datetimes. `civil_days()` = `(date_b - date_a).days` on `datetime.date` objects only. Test 17→29 Sep = 12 and 29→17 Sep = −12. [2026-09-10]
- **`round()` is banker's rounding in Python 3** (`round(2.5) == 2`); Jython 2.7 rounded half away from zero. `pct = int(round(100.0 * planned / capacity))` can differ by 1 at exact .5 — decided OD-8: keep Python 3 semantics, documented not patched. [2026-09-10]
- **`get_settings()` is `lru_cache`d.** A watchfiles reload does **not** pick up a `.env` change — restart the server. Any test that flips env must call `get_settings.cache_clear()`. And `.env` edits have silently failed to reach disk from a chained PowerShell heredoc: verify with `Select-String` before blaming code. [2026-09-11]
- **uv on Windows:** install via the standalone installer or winget, then open a **new** terminal (PATH). `uv run` always uses the project venv — never `pip install` into it by hand. `uvx` = `uv tool run`. `uv run` must be invoked from inside the project, or it reports `program not found`. [2026-09-11]
- **A winget-pinned installer can be dead with a good hash.** `winget install -e --id Microsoft.SQLServer.2022.Developer` verified its hash, ran and died — `FatalActivityException: This version of the installer is no longer supported`, exit 3762504530. The package ships the SSEI *bootstrapper*, not media, and Microsoft retires old stubs; the hash passing is what proves it is not a corrupt download. Same family as S0 losing `web/` to a CLI flag that had stopped existing. It also turned out not to be needed — carry-backs to KT are scripts (§B), so no 2022 instance is wanted. [2026-09-14]
- **Windows PowerShell 5.1 reads a BOM-less UTF-8 `.ps1` as ANSI.** Non-ASCII in a script (a `§` in a banner) renders as `Â§`. Delivered `.ps1` files are ASCII-only, or carry a BOM. [2026-09-12]
- **A new PowerShell window opens in `C:\windows\system32`.** Every pasted block starts with `cd C:\dev\workmate-saas…`, or the first four commands fail on path and the fifth does something in the wrong tree. [2026-09-12]
- **PowerShell formats the second object type with the first one's table.** Two pipelines of different object types into one output stream — `Get-CimInstance … | Select-Object Name, StartName` then `Get-Item $bak | Select-Object Name, Length, LastWriteTime` in one block — and the second is rendered under the first's column headers: `Length` and `LastWriteTime` vanish without a word, and the "is the download intact" check produces no answer while looking like it did. `Format-List` the verification line, or run it in its own block. [2026-09-13]
- **`Format-List` on a collection of paths is not `Format-List` on one.** `Get-Item $map.Values | Format-List` passed the whole collection as a single path string and threw `PathNotFound` — after the copies had already happened, so only the size printout was lost and the block looked like it had failed. Loop the collection (`foreach ($p in $map.Values) { Get-Item $p | Format-List }`). [2026-09-14]
- **Pasting a block while the previous output is still scrolling overprints the echo.** The input is interleaved with result rows, the file on disk is correct, the re-run is clean — and the paste record is unreadable. Wait for the prompt before the next block. [2026-09-13]
- **The `app.frontend()` mount branch emits nothing.** With `dist/` present, the only boot-time evidence is the absence of `[G] frontend not built`. Log a positive `[F] frontend mounted dist=…` line; an absence is only evidence when the whole sequence is visible. [2026-09-12]
- **The diag middleware is scoped to `/api`.** `GET /` gets a uvicorn access line and no diag line; `/api/v1/…` misses do. Deliberate or not, an SPA request is invisible to the forensic log — write the scope down where the middleware lives. [2026-09-12]
- **Once `dist/` exists, an `/api/…` miss with `Accept: text/html` is served `index.html` AND logged `[F] … 200`** — the instrument reports an API miss as a hit. `curl`/`TestClient` send `*/*` and still get the JSON 404, so the suite stays green while a browser typo on an API path silently "succeeds". S7 fixes the mount; until then, read the `[F]` on an `/api/` path with suspicion if the status is 200 and the path is not a route. [2026-09-12]
- **A slice that creates or changes `web/dist` changes backend behaviour without touching backend source.** Re-run the backend suite with `dist/` present before committing; `test_root_matches_the_frontend_state` was written to survive the flip and did. [2026-09-12]
- **`uv` defaults new interpreters to 3.14** now; this project pins `.python-version` = 3.13 until wheels are verified. [2026-09-10]
- **Delivered `.py` files no longer pass through a markdown renderer** (that was the Ignition Script Console path) — bare URLs and backslashes are safe again. But files are still delivered as raw source, never inline, and **`Unblock-File` in `Downloads` is not a copy**: check `Length` on the *target* after every drop. A smoke that reproduces the previous failure exactly is evidence the drop failed, not that the fix failed. **And Downloads is not a staging area:** a card presented in chat is not on disk until it has been saved — a drop block run before the save copies nothing, and `git add -A` commits the slice without it (S1g shipped without its spec, fixed in `0cb41b8`); a drop block re-run after the sources were moved out of Downloads copied nothing and *said* nothing. **Second session running:** the five compiled-doc cards were presented, the laptop rebooted before they were saved, and only the alphabetical gaps in a Downloads screenshot showed it. **Third session running:** the S1h spec was never saved out of Downloads, so the slice commit carried eight files instead of nine and the spec needed its own commit (`85d4e95`). The block's `Test-Path`/`Length` line on the targets is the evidence a drop happened; the copy's silence is not. Save every card before the block that copies it runs — and **every block that copies from Downloads begins with `Test-Path` on each source and prints it**, so a missing card fails loudly on line one instead of two screens later. **Fourth session: held** — fourteen S1i cards and the spec through a block that began with `Test-Path` on each source, and the slice commit carried all seventeen paths. **Fifth session: held again** — eight S1j cards plus the spec, ten paths in `f851889`, zero losses. Keep the block. [2026-09-11; Downloads rule 2026-09-13, repeated 2026-09-13, third loss 2026-09-13; held 2026-09-14, held again 2026-09-14]
- **"Add to project" is greyed out for an extension project knowledge does not allow.** `Azztec_SaaS_alembic_script_mako_v1_0_0.mako` offered Download and Print only; the disk copy keeps `script.py.mako` because Alembic requires that name, and project knowledge holds a byte-identical `.txt` twin. A card whose target filename has an unusual extension ships its `.txt` twin at the moment the card is cut, not after. [2026-09-14]

- **Read `request.state.actor` after `call_next`, never before.** Middleware runs before dependencies resolve; the actor exists only once the route's `get_current_actor` has run. Before D1a the outcome line carried user 0 on every request while the router's own line carried the real id — measured on the S1k smoke (2026-09-19).
- **Persistence never switches on under `WORKMATE_ENV=test`.** The suite boots the real app against the real `.env`, so a writer that is on would file the self-test marker and every `[G]` a test provokes into RST on every `pytest` run. `main.py` guards it; `test_kt_uplift`'s Marker Law case is the tripwire that caught it.
- **A persist path that swallows its errors is KT's own recorded failure** (`workmate.diag` 1.3.0: the live gateway's table stayed empty for weeks). The writer counts written / failed / dropped, prints one stdout `[E]` on the first failed batch, and the self-test reads its own row back. "No error" is not "it wrote".
- **`fastapi dev` runs the app in two processes** (reloader + server), so anything started in `create_app` exists twice. Start threads in the lifespan; the writer is one per process and that is fine, but a scheduled task must be guarded or it runs twice.
- **Killing the uvicorn reloader orphans the server child on Windows.** The child keeps the inherited port-8000 socket, keeps serving, and keeps its cached settings; Windows lets a second server bind alongside it, so requests split between two processes — which is how a fresh boot with `.env` at 21 answered `actor: 1`. Stop the child (the `Started server process [pid]` line), or close the window, and prove exactly one PID listens (`Get-NetTCPConnection -LocalPort 8000 -State Listen`) before believing a result.
- **A running dev server reloads onto a drop mid-copy.** `watchfiles` picked up D1a's files as they landed and the old server started writing to `Diag_Log` with the new code — the first four rows in that table. Stop the server before a drop, or accept that the reload is the first smoke.

## B. SQLAlchemy / pyodbc / MSSQL / PostgreSQL

- **ODBC Driver 18 defaults to `Encrypt=yes`** and rejects the local instance's self-signed certificate: `SSL Provider: The certificate chain was issued by an authority that is not trusted`. Dev fix: `TrustServerCertificate=yes` in the connection string (already in `.env.example`). Prod: a real cert or `Encrypt=strict` with a trusted CA. **`sqlcmd` under ODBC 18 needs `-C` for the same reason** (hit again 2026-09-13), and `sqlcmd -S localhost -E -C` under the Windows login (`AzztecDev\Azzte`, sysadmin) does everything `svc_workmate` cannot — SSMS is not needed for `sp_configure`. [2026-09-10; sqlcmd 2026-09-13]
- **URL-encode the ODBC string:** build with `urllib.parse.quote_plus(...)` and `mssql+pyodbc:///?odbc_connect=…`. A raw `Driver={ODBC Driver 18 for SQL Server}` in the URL breaks on the braces/spaces. `db.py` does this. [2026-09-10]
- **Never key a cache on the engine URL.** The MSSQL `odbc_connect` URL carries the password in its query string and SQLAlchemy's `hide_password` does not mask it — a URL-keyed cache parks the service account's password in a module global. Key on the `Engine` object. [2026-09-11]
- **Double pooling:** pyodbc pools connections itself; SQLAlchemy pools too. Set `pyodbc.pooling = False` **before** `create_engine` (SQLAlchemy's own recommendation for the mssql dialect). `db.py` does this. [2026-09-10]
- **`fast_executemany=True`** on the engine for bulk inserts; `pool_pre_ping=True` to survive idle-connection drops. [2026-09-10]
- **`char(n)` padding:** every legacy `char` column (`Short_WO_Id char(25)`, `Status char(1)`, `WO_Title char(70)`, `Users.Active char(1)`…) comes back space-padded. `RTRIM()` in SQL as the Ignition code does **and** `.strip()` in the mapper; compare with `RTRIM(x) = 'Y'`, never `x = 'Y'` unless you know the column is `varchar`. [2026-09-10]
- **`:name` in a SQL comment is a bind parameter** for SQLAlchemy `text()` too (regex-based, comments are not stripped) — the Ignition COLON-IN-COMMENT landmine survives. No colons in SQL comments; escape a literal colon as `\:`. [2026-09-10]
- **`Select` is a column name in this schema and a reserved word on both engines.** `WO_Responsible_User.[Select]` (the active flag) must be written `r."Select"` in portable SQL — double quotes are the ANSI form, and MSSQL accepts them under the default `QUOTED_IDENTIFIER ON`, which is what SQLAlchemy's connections carry. `[Select]` would need a `PG-CONVERT` tag; the quoted form needs none. [2026-09-19]
- **A leading-wildcard `LIKE` cannot use an index, and the legacy search is built on one.** `Short_WO_Id LIKE CONCAT('%', :q, '%') OR WO_Title LIKE …` over RST's 169,678 headers measures **~850 ms**, against 76 ms for the same query with no term and 122 ms for a 23-join single-row read. It is what the oracle's own named query does, so it is parity — but it is also the .NET app's reputation for being slow, and it is the first thing to look at when a list feels sluggish (item 53). A prefix match (`CONCAT(:q, '%')`) is sargable if the search term is ever constrained to a short id. [2026-09-19]
- **`OFFSET … FETCH` needs `ORDER BY`** on MSSQL. `TOP 1` in correlated subqueries (the pin select) is MSSQL-only → `-- PG-CONVERT: TOP 1 -> LIMIT 1`. [2026-09-10]
- **No `CAST(NULL AS datetime)` in portable SQL.** `datetime` is not a PostgreSQL type name and MSSQL's `timestamp` is rowversion. Use a bare `NULL` — the value is `None` either way. [2026-09-11]
- **`GROUP BY … ORDER BY COUNT(*) DESC` with no tie-break is non-deterministic**, and worse when the answer is cached for the process lifetime. Always add a second key (`, UOM_Id`). Latent on one database is still a defect on the next. [2026-09-11]
- **`SCOPE_IDENTITY()` vs `RETURNING`:** never write either in module SQL; call `db.insert_returning_id(conn, sql, params)`. Avoid `OUTPUT INSERTED.*` — it fails on tables with triggers, and a 20-year-old DB has triggers. [2026-09-10]
- **MSSQL `datetime` precision is 3.33 ms** and `Request_Start_Date` carries a time of day on ~half the rows (probed at KT 2026-09-04; re-probe on RST). Key days on the DATE part; shift datetimes with wall-clock `timedelta(days=n)` (DST-safe because naive). [2026-09-10]
- **Legacy stored procedures return row counts** that confuse `fetchall()`; when calling a `wmsp_*` proc prefix `SET NOCOUNT ON;` in the same batch. Prefer plain SQL over procs except where the .NET write path is the contract (`wmsp_WO_N_HeaderInsertUpdate`). [2026-09-10]
- **Windows auth vs SQL auth:** `Trusted_Connection=yes` only works in-process as the logged-in Windows user. Services and Docker use the SQL login `svc_workmate`. [2026-09-10]
- **Alembic vs legacy schema:** never `alembic revision --autogenerate` against the 227 legacy tables (it will try to "fix" them) — `env.py` sets `target_metadata=None` on purpose, so there is nothing to autogenerate from. Migrations only create or extend Workmate-added objects; `version_table_schema="dbo"`. The KT uplift shipped as **`0001_kt_parity_additive`** (S1j, 2026-09-14, OD-43): scripted from `dbWorkmate_KT`'s catalog by `scripts/kt_uplift_ddl.py`, never typed, committed **static**, and `test_committed_migration_matches_the_kt_catalog` re-reads the oracle and asserts byte equality — a hand-edit to the migration is a red test. `alembic upgrade head --sql` (offline mode) is the migration's `DRY_RUN`: read the render, then run. Guard by name — `inspect().get_indexes()` excludes the PK, so PKs are guarded through `get_pk_constraint()`. [2026-09-10; uplift 2026-09-13; shipped 2026-09-14]
- **PostgreSQL folds unquoted identifiers to lowercase.** `SELECT WO_ID FROM dbo.WO_N_Header` works on PG only if the table was created lowercase (`wo_n_header`, `wo_id`) and the SQL never quotes identifiers. Rule (D-3): PG DDL is lowercase; SQL stays unquoted and mixed-case as today → portable without edits. [2026-09-10]
- **Booleans:** legacy `'Y'/'N'` and `'1'/'0'` char flags are data values; they migrate unchanged; never "fix" them in flight. [2026-09-10]
- **SQLAlchemy 2.1 is rc1** (2026-08-31); the `mssql+mssqlpython` dialect and `greenlet`-optional asyncio land there. Pin `<2.1` until final, then a deliberate upgrade slice. [2026-09-10]
- **`sqlcmd -E` authenticates *you*; the engine opens the file as `NT Service\MSSQLSERVER`.** A `.bak` under `C:\Users\<you>\Downloads` is unreadable to `RESTORE` with sysadmin rights and `Test-Path True`. **The OS error code is the diagnosis: 2 = path, 5 = ACL.** Put backups in a folder the service account can read (`C:\SQLBackups\`) and grant on the file. [2026-09-13]
- **A move within a volume keeps the file's old ACL; only a copy inherits the destination's.** Moving the `.bak` into `C:\SQLBackups\` and granting on the *folder* changed nothing for the file. `icacls <file> /reset`, then grant on the file — or copy instead of move. [2026-09-13]
- **`OBJECT_DEFINITION()`, `SCHEMA_NAME()` and `OBJECT_NAME()` resolve in the *current* database even when fed an id from a three-part name.** `OBJECT_ID('dbWorkmate_KT.dbo.GetWeekNoAndYear')` resolves fine; `OBJECT_DEFINITION()` of that id looks it up in `master` and returns `NULL` — which reads like an encrypted module and isn't. Join the remote `sys.*` views (`dbWorkmate_KT.sys.sql_modules`, `.sys.objects`, `.sys.schemas`) instead, and start every cross-database batch with `SELECT DB_NAME()` so the trap is visible. [2026-09-13]
- **`sqlcmd -W` and `-y 0` are mutually exclusive, and so are `-h -1` and `-y 0`.** The whole batch aborts before the file is read, so it reads like a query failure and isn't one. Trimmed columns (`-W`) for catalog output; a long `definition` gets its own call with `-y 0 -w 8000` — no `-W`, no `-h`. [2026-09-13]
- **A restore across engine majors upgrades the physical version on the way in** (KTSQL02's 957 → AzztecDev's 998), and the door only opens one way: nothing from AzztecDev (SQL Server 2025) can ever be restored onto KTSQL02 (SQL Server 2022). `dbWorkmate_KT` is a read-only oracle, never a staging copy for "push a fix back to KT".
